# 外部調査の指摘 F-101・F-102 への見解と対応方針

- 作成日: 2026-10-16
- 対象の指摘:
  - F-101 API の受講者一覧出力（Csv_download）にログイン確認・接続元制限が無い
  - F-102 CMS のバッチ処理用コントローラが Web から起動できる
- 確認に使ったソース: リポジトリのブランチ `NBR-240-secure`（セキュリティ対応中のブランチ）と `main`（本番と同じ版）

どちらの指摘も、早急に対応すべき内容と認識しています。以下に、指摘ごとの見解、現状、対応内容を示します。

---

## F-101 API の受講者一覧出力（Csv_download）

### 見解

指摘のとおりと認識しています。`Csv_download` は現在使用していない処理で、セキュリティ対応の中で削除する予定のコントローラです。他の修正の反映を待たず、先行して本番環境から削除できます。

### 現状

| 項目 | 状況 |
|---|---|
| 本番（`main`） | `alflearning/alflearning-api/application/controllers/Csv_download.php` が残っている。指摘のとおり、ログイン確認・接続元制限が無い |
| セキュリティ対応のブランチ | コミット `d30ff1b`（2026-10-08）で、ファイルごと削除済み。本番へは未反映 |
| 利用状況 | CMS の `Cms_student::csv_download()` に、この API の URL（`/csv_download`）を呼ぶ処理が残っている。ただし、CMS のどの画面からもこの処理へのリンクは無く、使われていない。API を削除しても、画面の機能への影響は無い |

### 対応内容

1. `Csv_download.php` を削除した版を、他の修正に先行して本番（API サーバー全台）と stg に反映する
2. CMS 側に残っている呼び出し元（`Cms_student::csv_download()` など）は、どこからも使われていないため、あわせて削除する（呼び出し元が残っていても、API の削除後は 404 になるだけで情報は返らない）

### 確認方法

- 反映後、`https://<API のドメイン>/csv_download` へのリクエストが 404 になること
- CMS の受講者一覧・検索など、既存の画面が従来どおり動くこと

## F-102 CMS のバッチ処理用コントローラ

### 見解

指摘のとおりと認識しています。バッチ処理は、本来サーバー内のコマンドライン（cron）からのみ実行するものです。CodeIgniter 3 には、コマンドラインからの実行かどうかを判定する関数 `is_cli()` が用意されています。これを使い、対象のコントローラすべてで、Web（HTTP）からの起動を拒否するようにします。

### 現状

- 本番（`main`）では、指摘のとおり、コマンドライン以外からの起動を拒む確認が有効になっていません（`Bat_data_import.php`・`Bat_data_import_test.php`・`Bat_goto_streamserver.php` の 3本で、確認の行 `//$this->input->is_cli_request()` がコメントアウトされている）。
- セキュリティ対応のブランチでは、15本で `is_cli()` を使っています。ただし、いずれもエラー表示の切り替え（`ini_set('display_errors', is_cli() ? 'On' : 'Off')`。Web の画面にはエラーを出さない）のためで、Web からの起動を拒む処理ではありません。
- 同じブランチで、使われていないバッチ 2本（`Bat_get_alfstream_reading_history_mst.php`・`Bat_get_alfstream_reading_history_oneoff.php`）を削除済みです（コミット `89a5e68`）。このため、今回の対象は指摘の 29本から 2本減り、`Material_convert.php`・`Stream_ftp.php` を含めて 28本になります。
- CMS のソースの中に、これらのコントローラを HTTP で呼び出している箇所はありませんでした。

### 対応内容

1. **Web からの起動の拒否**: 対象のコントローラすべてのコンストラクタの先頭に、次の確認を追加します。

   ```php
   function __construct()
   {
       parent::__construct();
       if (!is_cli()) {
           show_404();
       }
       // 以降は既存の処理
   }
   ```

   コンストラクタで確認するため、`index()` 以外の公開メソッド（例: `Bat_oneoff_import_student::oneoff_import()`）も、まとめて Web から起動できなくなります。

2. **一回限りの処理・試験用の処理の撤去**: データ移行用などの一回限りの処理と試験用の処理は、役目を終えているため、本番環境から撤去します（下の表の「撤去」）。受講者テーブルを全件消去する `Bat_oneoff_import_student.php` も、これに含まれます。

### 反映前の確認事項

- **cron の起動方法**: `is_cli()` の確認を入れると、HTTP（wget・curl など）で起動しているバッチは動かなくなります。crontab はリポジトリで管理されていないため、反映前にバッチサーバーの crontab を確認し、次の 2点を確かめます。
  - すべてのバッチが、コマンドライン（`php index.php <コントローラ名> <メソッド名>` の形）で起動されていること
  - 撤去するバッチが、cron に登録されていないこと
- HTTP で起動しているものがあった場合は、コマンドラインでの起動に切り替えてから反映します。

### 確認方法

- 反映後、Web から `https://<CMS のドメイン>/bat_mail` などのバッチの URL を開くと 404 になること（撤去したものも 404）
- cron からの定期処理が従来どおり動くこと（バッチサーバーのログで、反映後の初回実行を確認する）
