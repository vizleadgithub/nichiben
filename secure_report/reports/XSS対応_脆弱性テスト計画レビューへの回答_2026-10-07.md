# XSS対応 脆弱性テスト計画 レビューへの回答

テスト計画のレビューありがとうございます。
「再診断で指摘が出る可能性の箇所」として概要に挙げていただいた6点について、見解と対応方針を回答します。

6点とも「今回はやらない」とする範囲ではなく、以下の方針で進め、脆弱性テスト計画（XSS対応_脆弱性テスト計画.xlsx）を書き換えます。3章以降のご指摘も、この書き換えの中で反映します。

実施は、自動テストのスクリプトで網羅的に実行し（メール送信・削除など自動化の対象外とする操作は手動で実施）、検出された候補を人が再現確認して最終判定する形で、予定している ExC の確認までに行います。

※レビューは5/8時点のソースとの比較とのことですので、現在の修正ブランチ（NBR-240-secure）の状況も併記しています。

## 1. URLで到達できるファイル単位の突き合わせが無い（2.1）

**見解**: ご指摘のとおりです。ExCはURLを起点に全パラメータへ注入するため、入力欄を起点にした一覧だけでは網羅の根拠になりません。

**対応**:
- URLで到達できる全ファイル（CMSのコントローラの公開メソッドを含む）の一覧をソースから機械的に作成し、各ファイルに「テストする行」または「テストが不要な根拠（削除済み・到達できない等）」を対応づけた表を付録に追加します。表に空欄が無いことを完了条件に加えます。
- 修正ブランチの現状は次のとおりです。
  - 削除済み: `/exam/backup/`、`/exam2/backup/`、`/exam2/*_mst.php`、`/search/index20260323.php`、`/mypage/lesson_list2_test.php`、`/login/*.php.bak.*`、WordPress テーマの旧ファイル（`index_20260324.php`・`index_20260407.php`・`footer_20130920.php`）、`report_product/_info.php`・`__info.php`・`info_dev.php`、`alfproduct/admin/`（`testlogin` を含む）、APIの `Elm_api_test`
  - 残っている: `/exam2/resubmit_check_review.php`・`resubmit_exec_review.php`
  - 残っているものは、削除する（E-08で404を確認）か、残してテストするかを決めて表に記載します。
- CMSのバッチ（`Bat_*`、27本）は、コマンド実行のみに限定する判定が3本にしかありません。バッチを実際に動かさない方法（ルーティング・アクセス制限の設定と、ソース上の判定の確認）で URL から到達できるかを確認し、表に記載します。

## 2. 一覧を作った基準ソースが書かれていない（2.2）

**見解**: ご指摘のとおりです。

**対応**: 基準とするブランチ・コミット（NBR-240-secure の特定のコミット）を、計画書の1章（1_方針シート）に明記します。あわせて、検証環境に置かれているコードがそのコミットと一致していることを、テストの開始前に確認する手順を追加します（No.42 の差分一覧と合わせて実施）。

## 3. 入力チェックで弾かれた項目の表示側が未検証になる（2.3）

**見解**: ご指摘のとおりです。「拒否されたのでOK」では、別の入口（CSV取込・SSO・バッチ・過去データ）から入った値の表示を確認できません。

**対応**:
- 判定に「入力拒否（表示側は未検証）」を追加します。自動テストの結果から、入力で拒否された行を機械的に抽出します。
- 抽出した行は、別の入口か、データベースへの直接投入で値を入れ、表示側を確認します。
- 桁数の短い項目用の、短い攻撃文字列を付録に追加します。切り詰め・保存エラーになった場合の扱いも判定基準に追記します。

## 4. 権限（アカウント）が行に割り当てられていない（2.4）

**見解**: ご指摘のとおりです。特に「単位会の管理者が登録した値を、日弁連の管理者が見る」経路は、完了条件に入れるべきでした。

**対応**:
- 「入力する権限」「表示を確認する権限」の列を追加します。
- 全行を既定の権限（管理画面は日弁連の管理者、受講者サイトは通常の受講者）で実施します。
- 権限によって表示が変わる画面・項目は、その権限での確認を個別の行として追加し、確認しない組み合わせが出ないようにします。コードを確認したところ、権限によって出力の処理が変わる箇所は次のとおりで、追加は30行前後の見込みです。
  - 管理画面: メニュー、共通ヘッダー、単位会ごとの表示（5ファイル）
  - 商品管理: メルマガ、受講者検索、売上一覧、ライブ研修（支部）など（8ファイル・12か所）
  - 受講者サイト: マイページのトップ、代替倫理研修の画面
- 上記以外の画面は、権限によって変わるのが「画面に入れるかどうか」と「表示するデータの範囲」だけで、表示の処理は同じです。この確認は、1. の対応表を作る際に、コントローラーでの権限の判定も合わせて洗い出して裏付けます。
- 下位の権限から上位の権限への経路（単位会の管理者が登録 → 日弁連の管理者が表示、受講者が登録 → 管理者が表示）を、入口別の表示先と同じ形で行に追加し、完了条件に加えます。
- 実施は、自動テストのスクリプトに権限ごとのログインと巡回を追加して行います。
  - 使うアカウント: 日弁連の管理者、単位会の管理者、権限を限定した管理者、通常の受講者、代替倫理研修の権限がある受講者
  - F-10（自動追跡）も、各権限でログインした状態で巡回し、どの権限の画面で検出されたかを記録します。
- 未ログインでの直接アクセスは、1. の対応表で全ファイルを対象に確認します。

## 5. F-10（自動追跡）の中身と、日程・担当・工数が無い（2.5）

**見解**: ご指摘のとおりです。F-10 の仕様と、実施の日程が計画書に書かれていません。

**対応**:
- F-10 は、自動テストのスクリプトとして実装を進めています。計画書には次の仕様を記載します。
  - 攻撃文字列を登録したうえで、CMS・受講者サイトを巡回し、識別用の目印が出た位置を検出する
  - リンクで辿れないポップアップなどは、開始点として個別に指定する
  - alert などのダイアログは自動で閉じて記録し、画面上に目印の要素ができたかで検出する（処理が止まらない）
  - 削除・メール送信・決済などの操作は巡回の対象から外す
- 権限ごとのログイン状態での巡回は、4. のとおり自動テストのスクリプトに追加します。
- 日程・担当・工数を、ExC の確認に間に合わせる形で計画書に記載します。作業は次の流れで進めます。
  1. 計画の修正（列の追加、1. の対応表の作成）と、検証環境のコードの一致の確認
  2. データを書き込まないテスト（検索条件、確認画面までの入力、入力欄以外から入る値）の自動実行
  3. データベースのダンプを取ったうえで、データを書き込むテスト（F-10、権限ごとの巡回、入力拒否した行の表示側の確認）の自動実行
  4. 自動テストが検出した NG 候補を、人が再現確認して最終判定（OK/NG）し、計画書に記入
  5. メール送信を伴う画面など、自動化の対象外とした項目を人が実施
  6. NG を修正した場合は、該当の行を自動テストで再実行して確認
- 実データ（特定の受講者を特定の講座・注文へ紐付けて初めて表示が確認できる項目。講座確認の受講者一覧・売上の会員詳細/注文詳細など）は、調査の結果、CMS側の手動データ準備なしで自動テストに組み込めることが分かりました。残る項目（提出ファイル名の確認・領収書PDFの確認）は、対象機能の実装状況や必要なデータの条件を精査したうえで、ほかの項目と同じく ExC の確認までに対応します。
- 全行を人が手で実施することはせず、実行は自動テストで行い、人は NG 候補の確認と最終判定に集中します。
- 行ごとに「実施日・実施者・環境・ブラウザ・権限・証跡の場所・再テスト履歴」の列を追加します。自動テストの実行結果（日時・環境・証跡の場所）は、この列へ機械的に転記します。

## 6. 検証環境で実施することの副作用（2.6）

**見解**: ご指摘のとおりです。チームの作業ルールとしては定めていましたが、計画書に書かれていませんでした。

**対応**: 次のルールを、計画書の「1_方針」シートの「6. 環境・準備」に記載します。
- **メール送信**: メール送信を伴う画面・バッチ（注文詳細・入金アップロード・メルマガ・問い合わせ・決済など）は自動テストの対象外とし、送信先を限定したうえで手動で実施します。
- **破壊的な操作**: 削除・取消などの操作と、バッチの直接実行は自動テストの対象外とし、テスト専用のデータで手動で実施します。
- **データの復元**: 書き込みを伴うテストの前にデータベース全体のダンプを取り、テスト後はダンプから復元します（項目ごとの削除はしない）。
- **他の作業への影響**: テスト用データは名前の先頭に `[XSSTEST]` を付け、専用の講座・商品に限定します。全画面に表示される値（通知バナー・カテゴリ名など）への登録は、実施の時間帯を関係者と調整します。
- **動画視聴履歴の記録**: `/player/` 配下は再生開始のたびに視聴履歴が記録される副作用がありますが、専用のテストデータ・テスト用受講者に限定したうえで自動テストの対象に含めます（対象外にはしません）。記録された履歴は、書き込みテスト後のデータベース復元で元に戻します。
- **経路**: ExC が診断する経路と同じ経路（WAF・CDN の有無）で実施することを確認し、環境欄に明記します。
- 未記入だった受講者サイト・WordPress の検証環境の URL を記入します。
