### [B-0] 削除済みの PHP 関数 `mysql_real_escape_string()` の呼び出しが複数箇所に残存

PHP 5 時代の `mysql_*` 系関数は PHP 7.0 で削除されており、現在のサーバー（PHP 8.3.23、`mysql` 拡張は未ロード）では**呼び出すと必ず Fatal Error（Uncaught Error: Call to undefined function）になる**。リポジトリ全体を検索したが、代替定義（ポリフィル）は存在しない。

**該当（実際に呼ばれる経路があるものを確認した範囲）:**

| ファイル | 内容 | 呼び出し元（実際に到達する画面） |
|---|---|---|
| `alfproduct/public/mypage/edit.php`（19箇所、521〜 行） | 受講者本人の登録情報変更の確定処理（`update student set ...`） | `/mypage/edit.php`（受講者サイト、マイページ > 登録情報変更）。**保存ボタンを押すと必ず失敗し、氏名・メールアドレス等の変更ができない** |
| `alfproduct/module/functions_mst.php:2219` `get_bar_association_info()` | 単位会情報の取得 | `alfproduct/module/functions.php`、`product_lecture`・`product_lecture2` の `info_user.php`・`info_user_import.php`・`info_user_regist.php` |
| `alfproduct/module/functions_mst.php:2327-2329` `insert_wp_posted_article_product()` | 商品登録時の WordPress 自動投稿（お知らせ） | `alfproduct/product/add.php`・`alfproduct/product_live/add.php`（商品管理の新規登録完了時）。テスト計画 G-09（商品登録・更新時のお知らせ自動投稿）に該当 |

**対象外（念のため確認。実害なし）:** `alfproduct/public/exam2/backup/result_mst.php`・`result_review.php` は `backup` ディレクトリ配下で実行経路なし。`system/database/drivers/mysql/`（CI の古い DB ドライバ）・`admin/testlogin/`・WordPress の `cp-includes/class-wpdb.php` は、現在の DB 接続設定（`mysqli`/`pdo_mysql`）では使われない想定のコード。

**影響:**
- 受講者が自分の登録情報（氏名・メールアドレス・住所等）を変更できない（機能停止）。
- 商品管理で新規に商品を登録完了すると、WordPress へのお知らせ自動投稿の工程で失敗する可能性がある（商品登録自体が完了するか、ここで止まるかは要確認）。

**対応:** `mysql_real_escape_string($x)` を、現在使用している接続方式に合わせて `mysqli_real_escape_string($objDbConnect->connect, $x)` 等へ置き換える（同じファイル内の他の箇所は既にこの書き方になっており、該当箇所だけ古いまま残っていると見られる）。

**2026-10-09 対応済み・コードレビューで確認（新たな軽微な指摘あり）**: 上記3箇所とも `mysqli_real_escape_string()` へ置き換え済み。ただし `functions_mst.php` 自体は不要ファイルとして全削除され（`a494b16`）、`get_bar_association_info()`・`insert_wp_posted_article_product()` は `alfproduct/module/functions.php` に移設されていた。**移設後の `get_bar_association_info()` に、`$bar_association_branch_id` を未エスケープのままSQLに連結している箇所が新たに見つかった**（エスケープ処理の移植漏れとみられる）。クラッシュはしない（型は文字列のため）が、SQLインジェクションの可能性があるため、他のSQLインジェクション対応（[B-15]〜[B-17]）と合わせてエスケープを追加することを推奨。

### [B-8] 商品管理の CSV 出力 3 画面に、ログイン確認が無い（3画面ともサーバー上への無条件のファイル書き込みを伴う）

**ファイル:** `alflearning-cms/alfproduct/report_product/csv_file.php`・`csv_file_utf.php`・`amount_product/csv_file.php`

同じディレクトリの `index.php`（通常の画面）は、先頭で次のとおりセッションを確認し、未ログインなら `/` へリダイレクトしている。

```php
include("/srv/alfproduct/module/module.php");
...
$objAlfSession = new AlfSession();
$arr_session = $objAlfSession->session_check();
if(!$arr_session){
    header("Location: /?backurl=".$_SERVER['PHP_SELF']);
    exit();
}
```

一方 `report_product/csv_file.php`・`csv_file_utf.php`・`amount_product/csv_file.php` の3ファイルは `include( "/srv/alfproduct/module/DbConnect.php" );` のみで、`module.php` の include も `AlfSession::session_check()` の呼び出しも無い（3ファイルとも `$_SESSION`・`AlfSession`・`session_check` の出現 0 件を確認）。**ログインしていない状態で直接 URL にアクセスしても、そのまま CSV が出力される。**

**追加で確認した影響（2026-10-07）:** この3ファイルは、呼ばれるたびに `touch($sPath)`・`fopen($sPath,"ab")`・`flock`・`fwrite` で `/tmp/` 配下のファイル（タイムスタンプ付きファイル名）へ無条件に書き込む処理を含む。認証が無いため、**誰でも何度でも呼び出せ、サーバー上に `/tmp/` ファイルを際限なく作成させられる**（ディスク枯渇・DoS的な副作用の懸念）。この書き込み処理自体の目的（ロック・一時ファイルの用途）は未調査。

**影響（CSVの中身）:** `report_product/csv_file.php`・`csv_file_utf.php` は `$pid`（商品ID）が空文字のまま初期化され、リクエストから上書きされる経路も無いため（`$_GET`・`$_POST` の参照が無い）、個別商品の詳細ではなく「商品ごとの受講状況サマリー」（商品ID・商品名・商品コード・弁護士会名・実施日・受講者数・受講完了者数 等）の全件が、ログイン無しで誰でもダウンロードできる状態と見られる（stg2 では未検証。実際の到達性・出力内容はブラウザでの確認が必要）。`amount_product/csv_file.php` も同様に未認証だが、出力内容の詳細は未調査。

**対応:** `index.php` と同じ `module.php` の include・`AlfSession::session_check()` のチェックを、3ファイルの先頭に追加する。あわせて `/tmp/` への書き込み処理が本当に必要か（不要なら削除、必要なら書き込み先・頻度を制限する）を確認する。

**自動テストでの扱い:** この3ファイルは無条件のファイル書き込みを伴うため、`run-xss-http.js` の自動テスト(E-52)では意図的にアクセスしていない（本項目の指摘のみに留める）。

### [B-12] 動画プレイヤーの Ajax エンドポイント3本が、ログイン確認が無いうえ `student_id` をリクエストから無検証で受け取る（他人の視聴履歴・受講完了フラグを改ざん可能）

2026-10-08、テスト計画 E-59（Ajaxエンドポイントの応答反射確認）の自動化可否を調査する過程で発見。

**ファイル:** `alfproduct/public/player/bookmark.php`・`insert_report_user_video_viewed.php`・`bookmark_delete.php`

3ファイルとも `include("…/module/bookmark_module.php")` と `DbConnect` のみで、`AlfSession`・`session_check`・`$_SESSION` の参照が一切無い（ログイン確認が無い）。そのうえで `$_GET['student_id']`・`$_GET['movie_id']` をそのまま使い、`cmCheckInput($student_id, 'CK_NUM')` で**数値形式であること**しか確認していない（＝ログイン中の本人の ID と一致するかは一切確認していない）。

```php
if (isset($_GET['student_id']) && isset($_GET['movie_id']) && isset($_GET['time'])){
    $student_id = $_GET['student_id'];
    $movie_id = $_GET['movie_id'];
    ...
    if(!cmCheckInput($student_id, 'CK_NUM') && !cmCheckInput($movie_id, 'CK_NUM')){
        // ブックマークの更新（INSERT ... ON DUPLICATE KEY UPDATE）
        ...
        // 視聴完了時間に達していれば report_user_video_viewed.complete_flag='1'、
        // さらに tbl_order_detail.video_complete_flg='1' まで更新する
```

**影響:** ログインしているかどうかに関わらず（＝セッションが無くても）、数値の `student_id`・`movie_id` を変えて直接アクセスするだけで、**任意の受講者になりすまして**次が可能:
- `bookmark.php` / `insert_report_user_video_viewed.php`: 他人の動画の再生位置（ブックマーク）・視聴履歴（`report_user_video_viewed`）を書き換え、再生完了相当の時間を送るだけで `complete_flag='1'` と `tbl_order_detail.video_complete_flg='1'`（受講完了扱い）まで更新できる。
- `bookmark_delete.php`: 他人のブックマークを削除でき、同様に受講完了フラグも更新できる。

本システムは弁護士会の研修受講管理（倫理研修等）を扱うプラットフォームであり、「受講完了」は本来 ID 連携等の根拠になりうる情報のため、他人になりすましてこれを偽装・改ざんできる点は XSS よりも深刻な、データの正当性に関わる問題。

**自動テストでの扱い:** 応答は常に固定文字列 `"0"` のみを返し、入力値を一切反射しないため（E-59 が想定していた「応答への反射確認」の対象にはならない）、XSS としての自動チェックは実装していない（対象外として記録）。本項目は静的なソース確認のみで検出しており、他人の `student_id` を使った実アクセスは行っていない。

**対応:** 他の受講者サイトの画面と同様に `AlfSession::session_check()` を先頭に追加し、かつ `$_GET['student_id']` を使わず、ログイン中のセッションから取得した本人の `student_id` のみを使うように修正する（リクエストの `student_id` は無視するか、一致しない場合は拒否する）。

### [B-21] CMS の cron ログファイルが、ログイン確認なしで直接ダウンロードできる

### [B-15] 銀行振込データ取込（bank_upload）— CSV の「注文No」「商品ID」がエスケープなしで SQL に連結

**ファイル:** `alflearning-cms/alfproduct/bank_upload/index.php`

```php
// 146行目
$sql.= "tbl_order.order_no='".$data["order_no"]."' ";
$sql.= " OR lpad(tbl_order.order_no, 13, '0')='".$data["order_no"]."' ";
// 172行目
$sql.= " AND tbl_order_detail.product_id='".$data[1]."' ";
```
