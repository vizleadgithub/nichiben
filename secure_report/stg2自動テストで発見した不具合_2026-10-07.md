調査日: 2026-10-06〜2026-10-07
調査方法: `tools/stg2-e2e` の自動テスト（`run-xss-search.js`・`run-xss-http.js`・`run-xss-form.js`・`run-xss-student-exam.js`）による stg2 環境への実アクセス
調査範囲: CMS・商品管理・受講者サイト・WordPress（テスト計画 `secure_report/XSS対応_脆弱性テスト計画.xlsx` の自動化対象分、全 1476 行中 500 行を実行）

## 優先度: 最高（PHP 8 非互換。該当画面は現状必ず失敗する）

### [B-0] 削除済みの PHP 関数 `mysql_real_escape_string()` の呼び出しが複数箇所に残存

PHP 5 時代の `mysql_*` 系関数は PHP 7.0 で削除されており、現在のサーバー（PHP 8.3.23、`mysql` 拡張は未ロード）では**呼び出すと必ず Fatal Error（Uncaught Error: Call to undefined function）になる**。リポジトリ全体を検索したが、代替定義（ポリフィル）は存在しない。

**該当（実際に呼ばれる経路があるものを確認した範囲）:**

| ファイル | 内容 | 呼び出し元（実際に到達する画面） |
|---|---|---|
| `alfproduct/public/mypage/edit.php`（19箇所、521〜 行） | 受講者本人の登録情報変更の確定処理（`update student set ...`） | `/mypage/edit.php`（受講者サイト、マイページ > 登録情報変更）。**保存ボタンを押すと必ず失敗し、氏名・メールアドレス等の変更ができない** |
| `alfproduct/module/functions_mst.php:2219` `get_bar_association_info()` | 単位会情報の取得 | `alfproduct/module/functions.php`、`product_lecture`・`product_lecture2` の `info_user.php`・`info_user_import.php`・`info_user_regist.php` |
| `alfproduct/module/functions_mst.php:2327-2329` `insert_wp_posted_article_product()` | 商品登録時の WordPress 自動投稿（お知らせ） | `alfproduct/product/add.php`・`alfproduct/product_live/add.php`（商品管理の新規登録完了時）。テスト計画 G-09（商品登録・更新時のお知らせ自動投稿）に該当 |

**対象外（念のため確認。実害なし）:** `alfproduct/public/exam2/backup/result_mst.php`・`result_review.php` は `backup` ディレクトリ配下で実行経路なし。`system/database/drivers/mysql/`（CI の古い DB ドライバ）・`admin/testlogin/`・WordPress の `cp-includes/class-wpdb.php` は、現在の DB 接続設定（`mysqli`/`pdo_mysql`）では使われない想定のコード。

**影響:**
- 受講者が自分の登録情報（氏名・メールアドレス・住所等）を変更できない（機能停止）。
- 商品管理で新規に商品を登録完了すると、WordPress へのお知らせ自動投稿の工程で失敗する可能性がある（商品登録自体が完了するか、ここで止まるかは要確認）。
- 単位会情報を参照する複数の画面（受講者取込関連）でも同様のエラーが起こりうる。

**対応:** `mysql_real_escape_string($x)` を、現在使用している接続方式に合わせて `mysqli_real_escape_string($objDbConnect->connect, $x)` 等へ置き換える（同じファイル内の他の箇所は既にこの書き方になっており、該当箇所だけ古いまま残っていると見られる）。

### [B-8] 商品管理の CSV 出力 3 画面に、ログイン確認が無い（3画面ともサーバー上への無条件のファイル書き込みを伴う）

**ファイル:** `alflearning-cms/alfproduct/report_product/csv_file.php`・`csv_file_utf.php`・`amount_product/csv_file.php`

同じディレクトリの `index.php`（通常の画面）は、先頭で次のとおりセッションを確認し、未ログインなら `/` へリダイレクトしている。

```php
include("/srv/alfproduct/module/module.php");
...
$objAlfSession = new AlfSession();
$arr_session = $objAlfSession->session_check();
if(!$arr_session){
    header("Location: /?backurl=".$_SERVER['PHP_SELF']);
    exit();
}
```

一方 `report_product/csv_file.php`・`csv_file_utf.php`・`amount_product/csv_file.php` の3ファイルは `include( "/srv/alfproduct/module/DbConnect.php" );` のみで、`module.php` の include も `AlfSession::session_check()` の呼び出しも無い（3ファイルとも `$_SESSION`・`AlfSession`・`session_check` の出現 0 件を確認）。**ログインしていない状態で直接 URL にアクセスしても、そのまま CSV が出力される。**

**追加で確認した影響（2026-10-07）:** この3ファイルは、呼ばれるたびに `touch($sPath)`・`fopen($sPath,"ab")`・`flock`・`fwrite` で `/tmp/` 配下のファイル（タイムスタンプ付きファイル名）へ無条件に書き込む処理を含む。認証が無いため、**誰でも何度でも呼び出せ、サーバー上に `/tmp/` ファイルを際限なく作成させられる**（ディスク枯渇・DoS的な副作用の懸念）。この書き込み処理自体の目的（ロック・一時ファイルの用途）は未調査。

**影響（CSVの中身）:** `report_product/csv_file.php`・`csv_file_utf.php` は `$pid`（商品ID）が空文字のまま初期化され、リクエストから上書きされる経路も無いため（`$_GET`・`$_POST` の参照が無い）、個別商品の詳細ではなく「商品ごとの受講状況サマリー」（商品ID・商品名・商品コード・弁護士会名・実施日・受講者数・受講完了者数 等）の全件が、ログイン無しで誰でもダウンロードできる状態と見られる（stg2 では未検証。実際の到達性・出力内容はブラウザでの確認が必要）。`amount_product/csv_file.php` も同様に未認証だが、出力内容の詳細は未調査。

**対応:** `index.php` と同じ `module.php` の include・`AlfSession::session_check()` のチェックを、3ファイルの先頭に追加する。あわせて `/tmp/` への書き込み処理が本当に必要か（不要なら削除、必要なら書き込み先・頻度を制限する）を確認する。

**自動テストでの扱い:** この3ファイルは無条件のファイル書き込みを伴うため、`run-xss-http.js` の自動テスト(E-52)では意図的にアクセスしていない（本項目の指摘のみに留める）。

### [B-7] CMS ログインの戻り先（backurl）にオープンリダイレクトの脆弱性

**ファイル:** `alflearning-cms/application/controllers/Login_page.php` の `_is_valid_backurl()`

**該当コード:**
```php
private function _is_valid_backurl($url) {
    // / で始まる場合（自サイト内へのリダイレクト許可）
    if (preg_match('#^/.*#', $url)) {
        return true;
    }
    ...
}
```

**原因:** 「`/` で始まるか」しか確認していない。`//evil.example/` も `/` で始まるため許可されるが、ブラウザはこれを**プロトコル相対 URL**として扱い、外部サイト（`https://evil.example/`）へ遷移する。`/\evil.example`（バックスラッシュ）も一部のブラウザで同様に外部サイトへの遷移に使われる。

**再現:** `/?backurl=%2F%2Fevil.example%2F`(= `//evil.example/`) を付けて CMS にログインすると、ログイン完了後に `evil.example` へリダイレクトされる(stg2 で実機確認予定。`run-xss-http.js` の F-01 に実装済み)。

**影響:** フィッシングの踏み台にされる（ログイン成功後に外部サイトへ自動遷移するため、正規サイトのログインを装った誘導がしやすい）。

**対応:** `_is_valid_backurl()` を、`/` で始まり、かつ**2文字目が `/` でない**（`/\` も含めて弾く）ことを確認するよう修正する。例: `preg_match('#^/(?!/|\\\\).*#', $url)`。

### [B-2] CMS「受講者」新規登録 — 受講講座を選んでも「必須です」エラーになり登録できない

**画面:** `/cms_student/edit`（新規登録）・`/cms_student_sub_auth/edit`（新規登録）
**再現:** 受講講座のチェックボックスを1つ以上選択して登録確認へ進んでも、「受講講座 欄は必須です。」のエラーになり、確認画面に進めない。選んだ講座の数・組み合わせによらず常に発生する。

**該当コード:**
```php
// alflearning-cms/application/controllers/Cms_student.php:494
// alflearning-cms/application/controllers/Cms_student_sub_auth.php:481
$this->form_validation->set_rules('student_lectures', $this->lang->line_or_def('common_attendance_class','受講講座'), 'required');
```

**原因:** `student_lectures` は `<input type="checkbox" name="student_lectures[]">` という配列項目だが、`set_rules()` の第1引数に `[]` が付いていない。CodeIgniter 3 の `Form_validation::_execute()` は、ルール登録名に `[]` が無いのに POST 値が配列だった場合、「クライアント側で改ざんされた入力」とみなして**常に空として扱う**仕様がある（`system/libraries/Form_validation.php` 626行目付近のコメント: 「If we get an array field, but it's not expected... we'll just consider it an empty field」）。そのため `required` チェックが常に失敗する。

**裏付け:** 実際に送信された POST データ（`student_lectures%5B%5D=1`）を確認し、ブラウザ側は正しく送信していることを確認済み。サーバー側の検証ロジックの問題と断定できる。

**関連箇所（同じ誤りを横展開で発見）:**
```php
// alflearning-cms/application/controllers/Cms_exam2_review.php:607
$this->form_validation->set_rules('exam2_lectures' , '所属講座', 'required');
```
こちらも同様に `[]` が付いていない。`Cms_exam.php`・`Cms_exam2.php` 本体では `exam_lectures[]`・`exam2_lectures[]` と正しく `[]` が付いており、問題ない（比較のため記載）。

**影響:** 受講者の新規登録画面・権限限定受講者の新規登録画面から、**受講講座を割り当てての新規登録が一切できない**（必須チェックを回避する手段がない）。

**対応:** `set_rules('student_lectures[]', ...)` のように `[]` を付ける（`Cms_exam2_review.php` の `exam2_lectures` も同様）。

### [B-3] エラー画面にサーバー内部パス・スタックトレースが表示される（情報漏えい、複数画面）

**該当（今回のテストで確認した範囲）:**
- 受講者サイト: `/product/detail.php`・`/product/list.php` 系・`/mypage/buy_detail.php`・`/alfproduct/report_product/info.php` など（数値パラメータに不正な値・配列・巨大数を与えた場合。F-06・E-19 で確認）

```
Uncaught Error: Call to undefined function smarty_modifier_escape() in
/srv/alfproduct/smarty/templates_c/admin/...main_frame.tpl.php:8
```
```
must be of type string, array given in /srv/alfproduct/module/value_check.php:34
```

### [B-5] CMS「管理者（権限）」一覧検索 — 入力した記号が往復で変化する

### [B-6]（解消済み）商品管理の全画面が 500 エラー — templates_c のキャッシュ不整合

2026-10-07 の調査時点で、商品管理（`/alfproduct/*`）の全画面が下記のエラーで 500 になっていた。

```
Uncaught Error: Call to undefined function smarty_modifier_escape() in
/srv/alfproduct/smarty/templates_c/admin/%%B7^B7E^B7E43223%%main_frame.tpl.php:8
```

リポジトリには該当関数（`alfproduct/smarty/plugins/modifier.escape.php`）が存在するため、コードの不具合ではなく `templates_c`（コンパイル済みテンプレートのキャッシュ）が壊れている状態と判断。ご担当にて `templates_c` のキャッシュ再生成を実施いただき、解消を確認済み。

**参考:** F-06・E-19（テスト計画の重点項目・入口以外HTTP）で報告していた「エラー画面にスタックトレースが出る」という指摘のうち、商品管理側の一部はこの事象が原因だった可能性がある。
